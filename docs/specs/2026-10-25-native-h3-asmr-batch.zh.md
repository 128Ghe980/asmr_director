# H3 原生 ASMR 触发音批量试验

用户希望先试听 H3 直接生成的 ASMR 质量，并确认先准备 12 种常见触发音。当前 Audio Quality V1 内交付一个可搬到目标 ComfyUI 主机的独立试跑包，沿用现有批跑器，不增加顶层路线阶段。

输入为用户的 `I:/temp/文生视频.json`。保持原模型、VAE、文本编码器、加速节点、20 步、24 fps 和 ResolutionSelector 配置；无参考输入，画面和声音由 H3 一起生成。原 Ref2VA 权重不替换，因此实测结论仅适用于该工作流。提示词依据官方 T2VA 三字段格式，每类一个独立静态近景，写清动作、触发材质与同步声音，无对白及配乐。用户补充要求时长可自定义，5 秒只作默认；内置提示词改用可重复的慢速动作与相对收尾，不限定固定秒数或次数。

项目包仍使用 `asmr-video-package` version 1，新增显式 `generationMode: "text-to-video"`。每镜 `kind: "ambient"`、`referenceMode: "new"`，不允许输入音频、角色参考或连续镜头。未声明该模式的旧包保持参考分镜语义和原输入指纹。文生模式不要求图片上传、尾帧、音频后处理或本机媒体工具。

打包器从具名控件及连线生成 API 图，校验所支持的工作流结构，移除注释和已折叠的输入辅助节点，将视频输出编号规范为运行器使用的 26。原 JSON 原字节另存；每类附带可导入 ComfyUI 的界面工作流。默认保留分辨率选择器连线；提示词、种子、时长与输出前缀由运行器逐候选注入。

窗口「每条时长」和 CLI `--duration-seconds` 可覆盖本次文生镜头时长，支持有限正小数；留空逐镜读取 `durationSeconds`，不回写项目，不改写用户自定义 prompt。打包器同名参数优先于每类时长和数据顶层默认时长；派生手动工作流时长节点及 API 首镜长度同步。源 JSON 和来源元数据保持原始内容。

按原 `round(seconds×24)` 后对齐到 `17n+5` 帧，生成帧数不超过节点 3600 帧上限，超限在提交前拒绝。默认 5 秒得到 124 帧，24 fps 下画面约 5.167 秒；不为整齐时长裁剪原生输出。每类候选数 N 由既有窗口/CLI 指定，总数为 12×N。时长变化纳入输入身份，保留旧结果，改回原时长可复用完整历史结果。保留稳定种子、逐候选状态、有限技术重试、未知任务对账、断点恢复与停止后续提交；不跨类引用尾帧。旧参考分镜包拒绝文生时长覆盖，原音时长与 5 秒环境镜头规则保持。

验收包括工作流转换一致性、12×N payload、无输入素材/替换音轨、旧运行器回归及模拟 ComfyUI 恢复。没有目标 ComfyUI 的真实 H3 输出时，不能声明实际音质或同步质量通过。结果由用户试听比较材质辨识、同步、杂音、人声污染和舒适度。
