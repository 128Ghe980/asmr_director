# 第一人称分镜与剧情 ASMR 叠加

日期：2026-10-28。此功能在当前 Audio Quality V1 内推进，不新增顶层路线。本文记录源码合同与验证范围，不代表已经部署或完成目标机 H3 试听。

## 创意与分镜风格

创意页提供「角色展示（原风格）」和「第一人称 · 跟随剧情」两个分镜风格。内部值分别为 `character_framing` 与 `listener_pov`。选择参考模板时，采用模板固定的风格并禁用独立选择；旧模板缺少风格字段时仍使用原风格。首个「禁令下的秘密交易」固定为原风格。

风格保存在策划 brief、工程 videoPlan 及语音工作区中，随采用、工程 JSON 和工作区切换保存。旧工程缺少该字段时不自动迁写、不改原 prompt。缺省与显式选择原风格的分镜来源指纹一致；改成第一人称使旧分镜需要更新，但不使已采用人声重新生成。用户已有分镜和原音仍保留。

第一人称的相机是听者的眼睛。分镜生成必须根据全稿、可靠匹配的逐段导演说明和前镜终态，维持听者所在位置、眼高、朝向，并在实际走动、转身、落座等事件中随其变化。S1 是与听者互动的角色；S1 移动不等于听者也移动，邀请、未来计划也不算听者已经行动。只允许合理的听者局部手部，不切换到拍摄听者正脸或全身的外部机位。

原风格的主视频 H3 prompt 保留原有可见说话人与完整 `fully_copy` 规则。第一人称仅在 S1 嘴部可见时要求口型同步；听者按剧情看路或道具时，S1 可以在画外继续说原台词，不能为了拍说话人将镜头强行转回原位。相邻第一人称分镜的 camera 说明作为听者位置/朝向上下文保留；原风格仍不把普通机位作为全稿继承约束。

## 每镜独立 ASMR 声音规划

每次新生成有声或无对白分镜，都在同一次文案 API 回复中要求 `asmrSound`：

```json
{
  "prompt": "具体英文材料、触发动作、声音质感与自然停顿描述",
  "postProcessing": {
    "start": {"pan": 0, "distance": "near"},
    "end": {"pan": 0, "distance": "near"},
    "movement": "static",
    "gainDb": -12
  }
}
```

`prompt` 是 1–2000 字符的独立声音描述；模型不能在此决定时长或素材路径。`pan` 为听者左负右正的 -1 至 1，距离使用既有 `far/mid/near/close/very_close`，移动使用既有七类枚举，增益范围 -36 至 6 dB。空间规划依据声音物体相对听者的位置，不能把画面特写或相机放大直接理解成贴耳。

声音遵循当前剧情实际发生的动作。没有显著触发动作时，可用符合场景的微弱材质/活动声，不无故添加刷子、敲击或其他道具；无对白镜头也必须规划。独立声音禁止对白、低语、人声、歌声和音乐，不复现台词，不提前播放未来动作。服务器将该描述包装为 H3 T2VA 三字段 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`；不添加不存在的参考图、参考音频或人物标签。

原主视频 prompt 不嵌入新增 ASMR，主视频仍使用既有人声或无对白环境音规则。旧分镜可以没有 `asmrSound`，保存、原 prompt 导出和原视频流程保持可读。整批校对能够修改完整 ASMR 对象，预览、应用和撤回使用同一来源指纹及逆补丁机制；只改声音规划不改原音或主视频提示词。

## 时长、导出与批跑

视频包继续使用 `asmr-video-package` version 1。每镜可附带 `asmrSound.prompt`（已包装的完整 H3 提示词）、`durationSeconds` 和 `postProcessing`。对白时长取导出音频的实际 WAV 时长；无对白镜头取自身时长，仍受现有 5 秒上限。批跑器再次测量输入，对白不会使用模型给出的时长或工程估时。段后等待不进入单镜声音。

ASMR 作为每镜、每候选独立的无参考 H3 音视频任务生成，随后使用其音轨。声音裁到当前镜头实际音频时长，画面按 24 fps 向上对齐到整帧；因此视频容器长度可能比精确音频长度多不足一帧。原始 H3 结果与任务回执保留。批跑先完成原视频，再完成 ASMR 任务，停止与恢复沿用独立提交身份和对账机制；ASMR 失败不能清除原视频。

勾选合片后，每个完整候选分别产出原版 `preview.mp4` 和叠加版 `preview-asmr.mp4`；多候选追加 `-c001` 等编号。叠加版逐镜执行 ASMR 后处理和混音，再按原顺序合并，不能把后镜音效提前到前镜。缺镜、缺声音规划或未完成的同号 ASMR 任务不生成不完整叠加版。仅改变 ASMR 增益或空间设置时复用已有视频/声音生成结果，只重做叠加合片。

后处理复用产品现有 D 空间渲染器与配置的 SOFA，通过包内 `custom_nodes/asmr_director_audio` 适配节点在目标 ComfyUI 执行；导出包附引擎、数据与依赖说明，用户需按说明将节点放入目标 ComfyUI 并重启。运行器本机仍不依赖 FFmpeg，也不自动安装依赖或启动服务。声音按一个物体声源处理：生成的立体声先合为单声道，经 D 渲染输出立体声，再按段内长度对齐；混音进行峰值保护。该模式不保存 H3 自带的双耳空间信息，原生音视频另行保留。

## 本轮验证与限制

后端 8 组、185 项测试覆盖旧工程、原 prompt 保留、第一人称与声音合同、实测时长、无对白生成、来源过期、整批校对和撤回；16 文件 ESLint 通过，完整 TypeScript 检查通过。导出、节点和批跑器验证结果由本轮主交接记录汇总。

真实文案 API 验证仅 2 次业务请求、2 次上游请求，模型 `deepseek-v4-pro`：6.25 秒全零合成 WAV 的门口到桌边对白镜，以及 4 秒桌边低头看书页的连续无对白镜。首镜明确前移到桌边且 S1 在右后方画外，次镜保持桌边俯视书页并规划手指摩擦。两镜均返回有效 ASMR 声音与空间参数；故意声明为 99 秒的音频 metadata 未覆盖实测 6.25 秒。QA 位于 `I:/AI/asmr_director/qa/storyboard/2026-10-28-pov-asmr/`，包括请求、完整结果、双 prompt、合成 WAV 和审阅摘要。

上述是真实提示词与规划验证；没有生成 TTS、ASR、H3 视频，未写入用户工程，也没有验收最终声音、物理声位或视觉质量。首镜的 API 将脚步、衣料和落手组合成单条声轨并选择 `approach`，其实际空间效果仍需试听；不能把 schema 通过或文字连贯当成听感通过。最终成片与目标 ComfyUI 节点兼容性仍以真实目标机执行结果为准。
