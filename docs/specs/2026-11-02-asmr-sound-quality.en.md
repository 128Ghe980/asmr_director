# Independent ASMR production and role-aware loudness balance

This is Audio Quality V1 work. Publish the existing baseline first, then address homogeneous sounds, weak ASMR character and uneven levels. Prompt correctness does not establish rendered-audio quality.

- Keep the main performance, including camera-facing pantomime. The independent source video is an ASMR recording for relaxation/sleep: one concrete material, actual contact, visible micro-deformation, distinctive timbre/envelope and intentional pauses. Compare neighboring sound intentions rather than repeating generic soft/dry/friction descriptions. No voices, breath or music; never add unrelated props to the main scene.
- Optional `asmrSound.role` is `trigger|ambience`. New plans state it explicitly; omitted legacy values retain their previous prompt and mixing behavior. Trigger sources use material close-ups; ambience does not receive mandatory contact/hand instructions. Editing, parts and review preserve explicit roles.
- Explicit roles enable `balanced-v1`. Measure the spatialized result and apply bounded constant gain to trigger tracks; dialogue overlays use their main audio as a reference. Ambient beds are only reduced, never amplified above their quiet source. Preserve silence, transients, inter-channel ratios and spatial trajectories, with true-peak protection.
- In balanced mode, gainDb maps to a bounded trim: −12 is neutral for triggers, −30 for ambience; trim is −6 to +6 dB (ambience maximum +3). The UI displays the relative trim. Legacy gain keeps its original meaning. Initial target levels remain subject to real-material listening review.
- Use a distinct `AsmrDirectorBalancedSpatialAudio` node so an old remote installation cannot silently ignore the feature. At runner level, role/policy identity invalidates only enhanced concatenation when manifest prompt text and duration stay unchanged. Selecting a new role for a legacy sound in the web editor also switches its prompt wrapper; exporting that change intentionally regenerates the affected sound. Level-only edits keep its H3 cache. Preserve original previews, historical outputs and recovery journals.
- Reuse the existing D engine, dependencies, ComfyUI and SOFA. Do not modify shared voice processing or add services. Supply the complete node update without rewriting existing projects automatically.

Validate role-specific prompts, representative real DP results, editor/review/ZIP/runner propagation, convergence of level-varied sources, quiet-source protection, dynamics/peak limits, legacy cache behavior and offline package payloads. Final H3 listening quality remains unverified until rendered on the target machine.
