AI ASMR Studio MVP 与技术路线报告

1. 项目定位

本项目不是单纯的“AI 生成 ASMR 音频工具”，而是一个面向音声创作者、同人创作者、短剧/游戏内容团队的 AI ASMR 导演台。

核心目标是：

«将一句创意自动拆解为剧本、角色、情绪、音效、双耳空间走位和可编辑时间线，并生成可发布的 ASMR 音频。»

相比普通的“LLM 写脚本 + TTS 生成语音 + 音效生成器”聚合工具，本项目的关键差异在于：  
用户拿到的不是一段黑盒音频，而是一个可编辑、可重生成、可导出的音声工程。

2. MVP 核心假设

2.1 用户痛点

当前用户如果想做 ASMR 音声，需要完成以下步骤：

1. 写创意和脚本；
2. 设计角色说话方式；
3. 找声优或用 TTS 生成语音；
4. 寻找雨声、呼吸、衣物摩擦、翻书、敲击等音效；
5. 在 DAW 中手动摆放音效；
6. 做左右耳声像、混响、EQ、压缩；
7. 反复修改某一句台词或某个音效；
8. 导出最终音频。

这个流程对普通创作者门槛很高。即使用上现有 AI 工具，也大多只是局部替代：LLM 只能写文本，TTS 只能生成人声，音效模型只能生成单个音效，缺少一个统一的“导演层”和“时间线层”。

2.2 MVP 假设

MVP 要验证的不是“AI 能不能生成声音”，而是验证：

1. 用户是否愿意从一句创意开始生成完整 ASMR 工程；
2. 用户是否认为“可编辑时间线”比“一键生成音频”更有价值；
3. 分段生成 + 质检 + 混音是否能显著提升长音频一致性；
4. 双耳走位和音效编排是否能形成明显产品差异；
5. 创作者是否愿意复用角色声音卡、场景模板和时间线工程。

3. MVP 产品形态

3.1 一句话输入

用户输入一个创意，例如：

«雨夜，年上姐姐轻声安慰失眠的你，整体温柔，有一点暧昧，中文，5 分钟，双耳 ASMR。»

系统输出一个完整项目，包括：

- 标题；
- 场景设定；
- 角色设定；
- 情绪曲线；
- 分段脚本；
- 音效清单；
- 左右耳走位；
- 生成参数；
- 可播放音频；
- 可编辑时间线。

3.2 导演分镜页

系统先不直接生成音频，而是生成一个“导演分镜”。

每一段包含：

- 时间范围；
- 台词；
- 情绪；
- 语速；
- 音量；
- 声像位置；
- 距离感；
- 背景音；
- 音效；
- 停顿；
- 备注。

示例：

{  
“start”: “00:42”,  
“end”: “00:51”,  
“type”: “voice”,  
“text”: “你还没睡吗？没关系，我陪你一会儿。”,  
“emotion”: “comforting”,  
“voice_style”: “whisper”,  
“pace”: “slow”,  
“position”: “left”,  
“distance”: “close”,  
“sfx_before”: [“blanket_rustle”],  
“sfx_after”: [“soft_breath”],  
“pause_after”: 1.8  
}

这一层是产品核心。它把不可控的 prompt 变成可编辑的音声工程。

3.3 音频时间线页

MVP 不需要做复杂 DAW，但需要有一个轻量时间线：

轨道分为：

1. 人声轨；
2. 呼吸/轻笑轨；
3. ASMR 音效轨；
4. 环境底噪轨；
5. 后期处理轨。

用户至少可以做这些操作：

- 播放整段；
- 单独播放某个片段；
- 修改某句台词；
- 修改情绪；
- 修改左耳/右耳/中间；
- 调整音效音量；
- 局部重新生成；
- 替换音效；
- 导出最终音频；
- 导出分轨音频。

3.4 局部重生成

这是 MVP 必须做的亮点功能。

用户点击某一句话，可以选择：

- 更温柔；
- 更害羞；
- 更困倦；
- 更贴耳；
- 更小声；
- 加停顿；
- 加轻笑；
- 移到左耳；
- 移到右耳；
- 重新生成这一句。

这会让用户感觉自己不是在“抽卡生成音频”，而是在“导演 AI 声优表演”。

4. MVP 功能范围

4.1 第一版只做 4 个场景模板

不要一开始做全类型 ASMR。MVP 应该限制场景，提高质量。

建议第一版只支持：

1. 雨夜陪伴；
2. 睡前安抚；
3. 翻书/学习陪伴；
4. 耳边轻声聊天。

这四类场景有共同特征：

- 文本结构简单；
- 情绪稳定；
- 音效需求可控；
- 容易体现双耳空间感；
- 适合做 3–5 分钟 demo；
- 对用户有明确吸引力。

4.2 第一版只支持 8 类音效

MVP 音效不需要多，但需要精。

建议内置：

1. 雨声；
2. 房间底噪；
3. 轻呼吸；
4. 被子摩擦；
5. 衣物摩擦；
6. 翻书；
7. 指尖轻敲；
8. 轻笑/气声。

其中雨声和房间底噪适合做循环底层；呼吸、衣物摩擦、翻书、轻敲适合做空间点缀。

4.3 第一版只支持 6 种空间动作

建议支持：

1. 中间说话；
2. 左耳说话；
3. 右耳说话；
4. 靠近；
5. 远离；
6. 左右移动。

这些空间动作可以用声像、音量、EQ、混响和轻微延迟实现，不一定要依赖复杂模型。

4.4 第一版只支持 6 种情绪/语气

建议支持：

1. 温柔；
2. 安抚；
3. 害羞；
4. 困倦；
5. 轻笑；
6. 低声耳语。

不要一开始做愤怒、崩溃、强烈哭腔等高难度情绪。ASMR MVP 的目标不是戏剧张力，而是“近、轻、稳、舒服”。

5. 技术路线总览

整体技术架构建议分为 7 层：

1. 创意理解层；
2. 剧本与导演 DSL 层；
3. 人声生成层；
4. 音效生成/调度层；
5. 空间混音层；
6. 自动质检层；
7. 导出与工程化层。

核心流程如下：

用户创意  
↓  
LLM 生成 ASMR 项目设定  
↓  
LLM 生成时间线 DSL  
↓  
脚本分段与参数标准化  
↓  
TTS 生成人声片段  
↓  
SFX 生成/检索音效片段  
↓  
双耳声像与后期混音  
↓  
ASR + 音色 + 响度质检  
↓  
局部重生成  
↓  
导出 MP3 / WAV / 分轨 / 项目 JSON

6. 关键模块设计

6.1 创意理解模块

输入：

雨夜，年上姐姐，温柔安慰失眠的你，5 分钟，中文，双耳 ASMR。

输出：

{  
“title”: “雨夜睡前陪伴”,  
“duration”: 300,  
“language”: “zh”,  
“scene”: “rainy_night_bedroom”,  
“character”: {  
“role”: “older_sister”,  
“personality”: [“gentle”, “mature”, “comforting”],  
“speech_style”: [“soft”, “slow”, “close”]  
},  
“emotion_curve”: [  
{“range”: “0-60s”, “emotion”: “gentle_intro”},  
{“range”: “60-180s”, “emotion”: “comforting”},  
{“range”: “180-260s”, “emotion”: “sleepy_whisper”},  
{“range”: “260-300s”, “emotion”: “fade_out”}  
]  
}

这一层重点不是写漂亮文案，而是把创意变成结构化项目参数。

6.2 ASMR 时间线 DSL

这是产品最重要的中间层。

建议定义统一 JSON Schema：

{  
“project_id”: “asmr_001”,  
“duration”: 300,  
“tracks”: [  
{  
“track_type”: “ambience”,  
“clips”: []  
},  
{  
“track_type”: “voice”,  
“clips”: []  
},  
{  
“track_type”: “sfx”,  
“clips”: []  
}  
],  
“mixing”: {  
“target_lufs”: -18,  
“binaural”: true,  
“master_limiter”: true  
}  
}

单个 clip 示例：

{  
“id”: “voice_012”,  
“track”: “voice”,  
“start”: 78.5,  
“duration”: 6.2,  
“text”: “我就在你旁边，不用担心。”,  
“emotion”: “comforting”,  
“style”: “whisper”,  
“speaker_id”: “voice_card_001”,  
“position”: {  
“pan”: -0.75,  
“distance”: “close”,  
“movement”: “static”  
},  
“generation”: {  
“model”: “indextts2”,  
“seed”: 12345,  
“temperature”: 0.7  
}  
}

有了 DSL，后续模型可以替换，但产品层不变。

6.3 人声生成模块

推荐路线

MVP 人声生成建议采用多后端策略，但前端只暴露统一参数。

默认后端：IndexTTS2

适合：

- 情绪化 TTS；
- zero-shot 克隆；
- 长文本分段；
- 时长控制；
- 角色音声。

推荐用法：

- 每段 5–15 秒；
- 同一角色固定 voice reference；
- 每段附带 emotion/style 参数；
- 生成后做 ASR 检查；
- 不合格片段自动重试。

备选后端：CosyVoice 3

适合：

- 中文稳定性；
- 多语言；
- 方言；
- 更稳的内容一致性；
- 长文本基础朗读。

建议作为“稳定模式”。

备选后端：Fish Speech S2

适合：

- whisper；
- laugh；
- 轻声标签；
- 更强的二创表现；
- 角色化语气。

建议作为“表现力模式”。

商业后端：ElevenLabs / Fish Audio API / MiniMax

适合：

- 快速 demo；
- 商用部署；
- 用户不想本地部署；
- 更省工程成本。

建议作为 SaaS 版本的可选后端。

6.4 音效模块

音效模块不要完全依赖 AI 生成。建议采用“音效库优先 + AI 生成补充”的混合路线。

音效来源

1. 授权音效库；
2. 自制高质量 ASMR 音效包；
3. Stable Audio Open；
4. AudioLDM / AudioGen；
5. ElevenLabs SFX API。

使用策略

音效类型| 推荐方案  
雨声、风声、房间底噪| AI 生成或音效库循环  
呼吸、轻笑、耳语气声| TTS/人声音效库优先  
翻书、衣物摩擦、敲击| 音效库优先，AI 生成补充  
特殊场景声| AI 生成  
长环境氛围| Stable Audio / 商业 SFX API

音效调度

LLM 不应该只生成“需要雨声”，而是生成具体调度：

{  
“sfx”: “blanket_rustle”,  
“start”: 34.2,  
“duration”: 2.1,  
“volume_db”: -26,  
“pan”: 0.65,  
“distance”: “near”,  
“fade_in”: 0.2,  
“fade_out”: 0.6  
}

6.5 双耳空间混音模块

这是 ASMR 产品的关键差异点。

MVP 可以先用工程方法实现，不必一开始做复杂 HRTF。

基础处理

1. pan 控制左右耳；
2. gain 控制远近；
3. high-shelf / low-pass 模拟距离；
4. early reflection / small room reverb 模拟空间；
5. micro delay 模拟贴耳位置；
6. fade in/out 避免突兀；
7. breath layer 低音量铺底。

空间参数

{  
“position”: “left_ear”,  
“pan”: -0.85,  
“distance”: “very_close”,  
“gain_db”: -3,  
“air_absorption”: 0.2,  
“reverb_send”: 0.05  
}

可视化

前端可以显示角色位置：

中间 → 靠近左耳 → 停顿 → 移动到右耳 → 远离

这会比传统音频播放器更有传播点。

6.6 自动质检模块

长音频一致性是壁垒。建议 MVP 就做基础自动质检。

质检项

1. ASR 回听检查漏字、错字；
2. 片段响度检查；
3. 静音/爆音检查；
4. 音色一致性检查；
5. 音频时长检查；
6. 片段之间淡入淡出检查；
7. 音效是否遮挡人声；
8. 左右声道是否过度偏移。

自动重试策略

当某段出现问题：

- ASR 差异过大：重新生成该句；
- 响度过低：增益修正；
- 爆音：降低增益或重生成；
- 时长不符合：调整语速或目标 duration；
- 音色漂移：更换 reference 或降低生成随机性；
- 情绪不稳定：换情绪 prompt 或走稳定模型。

6.7 导出模块

MVP 至少支持：

1. MP3；
2. WAV；
3. 分轨 WAV；
4. 项目 JSON；
5. 字幕 SRT；
6. 简易封面 prompt；
7. 平台标题和简介。

高级版本可支持：

- Reaper 工程；
- Premiere XML；
- DaVinci Resolve 可导入时间线；
- B站/YouTube 发布包；
- 角色声音卡导出。

7. MVP 技术栈建议

前端

建议：

- Next.js / React；
- Wavesurfer.js 或自研轻量 waveform；
- Timeline UI；
- Zustand / Redux 管理项目状态；
- TailwindCSS 快速搭界面。

核心页面：

1. 创意输入页；
2. 导演分镜页；
3. 时间线编辑页；
4. 声音卡管理页；
5. 导出页。

后端

建议：

- Python FastAPI；
- Celery / RQ 任务队列；
- Redis 做任务状态；
- PostgreSQL 存项目；
- S3 / R2 / MinIO 存音频；
- FFmpeg 做拼接和转码；
- librosa / pydub / pedalboard 做音频处理；
- Whisper 做 ASR 质检。

模型服务

建议每个模型独立服务化：

orchestrator-api  
├── llm-planner-service  
├── tts-service  
├── sfx-service  
├── mixing-service  
├── qa-service  
└── export-service

这样后续替换模型不会影响产品层。

数据库核心表

建议：

- users；
- projects；
- scenes；
- voice_cards；
- timeline_clips；
- generated_assets；
- render_jobs；
- qa_reports；
- export_records。

- 自动生成脚本；
- 自动生成时间线 JSON；

- 插入环境音；

«用户可以编辑每一句台词和每个音效。»

- 波形时间线；
- 单句重生成；

此版本重点验证用户留存。

V0.5：创作者导出

«从玩具变成创作者工具。»

- 分轨 WAV；
- SRT 字幕；

- 标题简介；

此版本重点验证商业化可能性。

9. MVP 成功指标

9.1 生成质量指标

建议记录：

1. ASR 字错误率；
2. 片段重生成次数；
3. 生成失败率；
4. 平均生成时长；
5. 最终音频响度；
6. 左右声道峰值差异；
7. 音色一致性分数；
8. 用户手动修改次数。

9.2 用户体验指标

建议记录：

1. 从创意到首版音频耗时；
2. 用户是否播放完整音频；
3. 用户是否使用局部重生成；
4. 用户是否修改时间线；
5. 用户是否导出；
6. 用户是否保存角色声音卡；
7. 用户是否二次生成同类作品。

9.3 内容质量主观评分

建议让测试用户给 1–5 分：

1. 声音自然度；
2. 情绪表现；
3. ASMR 贴耳感；
4. 音效真实感；
5. 长音频一致性；
6. 是否愿意发布；
7. 是否愿意继续编辑。

10. 差异化与护城河

10.1 不拼底层模型，拼导演层

底层 TTS 和音效模型都会快速迭代。产品不应该把壁垒建立在某一个模型上，而应该建立在：

- 时间线 DSL；
- ASMR 分镜；
- 情绪曲线；
- 双耳空间调度；
- 自动质检；
- 局部重生成；
- 创作者导出。

10.2 从“一键生成”变成“可控创作”

普通工具给用户一个结果。  
本产品给用户一个可以继续导演的工程。

这个差异能带来：

- 更高可控性；
- 更强创作参与感；
- 更低失败成本；
- 更适合长音频；
- 更容易形成用户资产。

10.3 长音频一致性是关键壁垒

短音频 demo 很容易做，3–10 分钟稳定 ASMR 才是难点。  
通过分段生成、自动质检、音色一致性检查和局部重生成，可以形成明显优势。

10.4 ASMR 场景模板是内容壁垒

长期可以积累：

- 雨夜陪伴模板；
- 睡前哄睡模板；
- 学习陪伴模板；
- 护理/理发/耳边聊天模板；
- 角色人格模板；
- 音效组合模板；
- 情绪曲线模板。

这些模板会逐渐变成产品资产。

11. 风险与解决方案

11.1 声音克隆合规风险

风险：

- 用户上传未授权声音；
- 克隆真人声音用于冒充；
- 平台发布后存在滥用可能。

解决方案：

- 上传参考音频时要求授权确认；
- 禁止克隆公众人物、主播、声优等未授权声音；
- 为生成音频添加水印或 provenance 标记；
- 保存生成记录；
- 对外发布前加入举报和审核机制；
- 默认提供原创角色声音，不鼓励用户克隆真人。

11.2 成人内容与平台风险

ASMR 容易靠近擦边内容。  
如果产品要公开发布，建议 MVP 阶段明确定位为：

- 睡前陪伴；
- 情绪安抚；
- 放松助眠；
- 学习陪伴；
- 轻声聊天。

避免一开始做过度暧昧或成人化路线，否则平台审核、支付和推广都会更难。

11.3 音效质量不稳定

AI 生成音效可能有噪声、突兀、不可控。

解决方案：

- 高频 ASMR 音效优先使用精选音效库；
- AI 生成只作为补充；
- 环境声可用 AI 生成；
- 所有音效统一响度、淡入淡出、降噪；
- 内置“安全音效包”，保证第一版质量。

11.4 长音频生成成本高

解决方案：

- 分段缓存；
- 局部重生成；
- 同一项目复用环境音；
- 同一角色复用参考 embedding；
- 低清预览 + 高清最终渲染；
- 队列化任务；
- 商业 API 与本地模型混合。

15. 最终建议

第一阶段不要追求“大而全”的 AI 音频平台，而应该做一个强场景、强体验、强差异化的 MVP：

«输入一句 ASMR 创意，生成一个可编辑的双耳音声时间线，并支持局部重生成和分轨导出。»

MVP 的成败关键不在于接入多少模型，而在于：

1. 时间线 DSL 是否稳定；
2. 分段生成是否好改；
3. 双耳空间感是否明显；
4. 情绪表演是否比普通 TTS 更自然；
5. 长音频一致性是否足够好；
6. 用户是否愿意在生成后继续编辑；
7. 导出的结果是否能真的发布。

最优先做的不是“训练新模型”，而是把现有模型组织成一个真正适合 ASMR 创作的导演系统。

一句话总结：

«这个产品应该做成“AI ASMR 导演台”，而不是“AI ASMR 生成器”。前者有创作工作流和工程资产，后者很容易变成普通功能聚合。»
