# 第 10 步：产品工作流硬化设计

日期：2026-07-12

## 目标

把当前“单个项目可生成、可混音”的工作台升级为一个本地优先、可以长期使用和恢复的产品工作流。用户应能管理多个项目、保留版本、看到真实音频波形，并在导出前明确知道项目是否就绪。

## 当前现实

- 第 7、8、9 步已经打通真实 voice、半真实非 voice、真实项目混音和 WAV 下载。
- 左侧项目栏里的“最近项目”和“项目列表”仍是占位文案。
- 项目只保存到一个 `localStorage` key，无法切换多个项目，也没有恢复点。
- Preview Layer 仍显示伪波形，尽管真实 WAV 已经存在。
- 项目校验能发现 schema 错误，但没有把“素材是否齐全、混音是否最新、音频是否削波”等信息组织成导出前质量检查。
- 本项目当前坚持本地优先。云端持久化、账号、计费、发布和协作需要部署、身份与商业策略，不应伪装成本地 MVP 已完成。

## 方案比较

### A. 本地产品闭环（采用）

使用版本化的 `localStorage` 项目库保存多个项目和版本元数据；使用本地 Next API 读取现有 WAV，计算真实波形和技术指标；在现有左栏、Preview Layer、右侧详情中完成工作流接线。

优点：与当前架构一致、无需新服务、能立即交付完整可用闭环、容易测试和迁移。限制：浏览器容量有限，项目文档适合放在本地存储，音频仍由 D 盘 runtime 保存。

### B. IndexedDB 项目库

用 IndexedDB 保存项目和版本。容量与事务能力更强，但会引入异步数据库层、迁移和测试复杂度。当前项目 JSON 很小，音频又不进入浏览器数据库，因此收益不足。

### C. 文件系统项目库

在 Next API 后面直接保存项目目录和版本文件。更接近桌面软件，但会把浏览器 UI 与本机服务生命周期强绑定，并需要定义跨设备路径、并发和备份策略。可作为未来桌面封装阶段升级方向。

## 交付范围

### 1. 本地多项目库

新增版本化的本地项目库 envelope：

- `version: 1`
- `currentProjectId`
- `projects[]`
- 每个项目记录当前 `AsmrProject`、更新时间和版本记录

首次加载时自动迁移旧的单项目 key；无旧数据时把内置 demo 注册为第一个项目。项目 JSON contract 不增加项目库字段。

用户可以：

- 新建一个基于当前 demo 结构、但清空生成资产与导出结果的项目
- 在项目列表中切换项目
- 复制当前项目
- 删除非最后一个项目
- 导入 JSON 后把它加入项目库，或更新同 ID 项目

### 2. 版本与恢复

项目仍自动保存当前状态。版本记录采取“显式版本 + 破坏性操作前安全版本”的方式，避免每次输入都制造大量快照。

- `留版本`：为当前项目保存一个命名为时间的恢复点
- 切换、重置或用同 ID 导入覆盖前：保留去重后的安全版本
- 每个项目最多保留 12 个版本
- 恢复版本只替换当前项目内容，不删除版本历史，并在恢复前再留一个安全版本

版本元数据和历史不进入导出的 Project JSON。

### 3. 真实 WAV 波形与音频分析

新增 `GET /api/assets/analysis?uri=<durable-uri>&bars=64`：

- 只接受本地 `asset://clip/...` 或 `asset://mix/...` URI
- 复用安全的资产路径解析和 PCM WAV 解码
- 返回归一化 peak bars、duration、sample rate、channels、peak dBFS、RMS dBFS、clipped sample count
- 不把分析结果写入 Project JSON；浏览器按当前可预览资产请求并缓存于组件状态

Preview Layer 有真实 mix 时优先显示 mix 波形；否则显示当前可播放 clip 的真实波形；没有真实资产时继续显示低调的待生成占位。

### 4. 质量检查

新增纯函数质量报告，聚合：

- schema 校验是否通过
- 所有可生成 clip 是否已有真实 durable asset
- WAV mix 是否存在且与当前项目 fingerprint 一致
- 音频分析是否成功
- mix 是否为双声道
- 是否存在接近 0 dBFS 或实际削波

质量项分为 `通过`、`注意`、`阻塞`。已有的生成与混音 readiness 继续作为真正的操作门禁；技术音频告警不会销毁或隐藏上一个可用 WAV，但会在下载前清晰提示。

### 5. UI 布局

- 左栏保留可折叠行为，展开后显示紧凑项目列表和 `新建`、`复制` 操作。
- 当前项目有清晰选中态；项目项显示更新时间和版本数量。
- 右侧详情在 Preview Layer 下方显示紧凑的“质量检查”和“版本记录”。
- 版本记录最多展示最近 5 条，每条提供恢复按钮。
- 按钮继续使用简短中文文案和 Lucide 图标。
- 不增加弹窗式营销说明，不牺牲中间 Timeline 空间。

## 数据流

1. 启动时读取项目库，迁移旧 key，选中 `currentProjectId`。
2. 编辑、生成成功或混音成功后，当前项目自动写回项目库。
3. 切换项目时先结束当前生成会话，再载入目标项目并更新 `currentProjectId`。
4. Preview Layer 根据 mix 或 selected clip durable URI 请求分析接口。
5. 分析结果与项目状态一起生成质量报告并渲染。
6. 版本恢复进入同一 `setEditableProject` 流程，随后自动保存。

## 错误处理

- 项目库损坏时忽略无效记录并回退到 demo，不让页面白屏。
- 浏览器存储不可用时工作台继续以内存模式运行，并显示本地保存不可用状态。
- 分析接口拒绝未知 scheme、非法 asset ID、非 WAV 或缺失文件。
- 波形请求失败时显示“波形不可用”，不影响已有试听和下载。
- 删除最后一个项目被禁止。

## 测试与验收

- 项目库迁移、保存、切换、复制、新建、删除、版本去重、上限和恢复均有纯函数测试。
- 音频分析用已知 PCM WAV 测试 bars、声道、峰值、RMS 和削波计数。
- 质量报告覆盖未生成、已生成但未混音、最新 mix、过期 mix、削波告警。
- 完整运行 test、lint、build。
- 浏览器验收项目切换、版本恢复、真实波形、质量检查、折叠布局和无控制台错误。

## 明确不做

- 本轮不实现云端持久化、账号、计费、发布、协作。
- 不把音频二进制存入 `localStorage` 或 Project JSON。
- 不实现完整 DAW 波形编辑、频谱图或母带分析套件。
- 不修改 Timeline DSL 顶层 schema。
