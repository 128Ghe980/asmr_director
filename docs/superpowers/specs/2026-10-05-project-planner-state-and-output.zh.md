# 工程策划状态与回复长度修复

日期：2026-10-05。现有阶段：音质 V1，仍进行中。

用户反馈新建项目后右侧仍显示原项目内容，另外3分钟策划稿触发模型长度上限。
复现主题：深夜，在外面收集了一天资源回家，并带回来一个精致的机械表给家里的
AI机器人作为生日礼物，末世题材。分别修复工程状态和模型输出预算，不新增顶层路线。

## 每工程策划工作区

策划编辑内容归属于当前工程。新建工程打开其空白策划区；切回及刷新恢复对应工程
文案和剧情背景。切工程前保存包括不足300ms的最新修改，取消原工程请求，拒绝迟到
文案/背景回包；波形回复也遵守取消边界。既有新音频工程模板不在本次状态修复范围。

保存键为 `ai-asmr-studio:v1:planner-draft:project:<encodedProjectId>`。旧全局键
`ai-asmr-studio:v1:planner-draft` 的原字节始终保留；只有原归属标记吻合，或当前
工程来源与旧稿完整文案及生成brief相同时，才能自动迁入；同主题重生稿的通用段ID
相同不能证明归属。无明确归属的
旧稿不自动显示在新工程，刷新亦如此；通过 **恢复旧版草稿** 显式恢复，当前稿可
撤回，原旧稿仍保留。项目库未加载时不把旧稿绑定到临时示例工程。

对应键没有草稿时可从 `plannerSource` 初始化；键读取失败时不自动覆盖原保存。
`plannerSource` 是采用时的原稿快照，工程/策划编辑不反向改写。保留旧工程、版本、
已采用音频、分镜与全局旧稿。按最新用户要求，此规则覆盖2026-10-01策划分镜spec
中“切工程保持独立全局工作稿”的旧规则。

## 回复长度

官方DeepSeek创意策划明确关闭思考，把completion预算用于完整JSON。整份生成按
1/3/5/10分钟设置4096/8192/12288/16384 tokens。其他兼容API及Ollama维持既有
边界，不把DeepSeek专用参数传给其他接口。短结构分析、CPU设置、取消和总时限仍
遵守自身策略。截断回复仍报错，不把残缺JSON当成功；不无限续写/重试，不把要求
用户缩短时长作为主要修复。

验证新建/切换/刷新、300ms内编辑、旧稿归属/恢复、原稿保留和迟到保护，以及模型
参数、时长预算、length/错误/取消/超时和共用分析回归。用用户原主题做一次有明确
时限的真实3分钟请求，结果保存到当前新工程对应的策划草稿键，以验证刷新与切换；
不采用到工程时间线。实际结果与限制写入开发记录。
