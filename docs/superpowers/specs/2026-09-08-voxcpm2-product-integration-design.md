Date: 2026-09-08; updated 2026-10-07. ## Goal and scope

The user accepted this Planner iteration and requested a recorded/pushed milestone followed by VoxCPM2 integration preparation. This design refines the approved Audio Quality V1 stage; it creates no new top-level stage. `docs/ROADMAP.md` remains canonical. One successful CLI output is insufficient, and this slice does not complete the whole audio-quality stage.

Retain GPT-SoVITS and existing non-voice generation. VoxCPM2 is optional; do not silently change defaults or switch voice models after failure. Selected-clip generation and safe adoption were the first slice. The selected long-text approach is now an additional mode of the same provider, with its current acceptance status recorded below.

## Requests, candidates and project state

Extend existing `GenerateClipRequest` with server-validated `voiceOptions`: provider, voicePackId, referenceMode and generationMode. `generation-bridge.ts`, the local bridge, clip API and `local-clip-generation.ts` share this request and discriminated results. Preserve legacy GPT and non-voice calls. Vox success returns a candidate instead of immediately replacing the asset through the current success callback.

Persist candidate manifests outside Git in runtime storage. Record project/clip identity, target text and request fingerprints, stable asset URI, WAV format/actual duration, engine/model/weight identity, actual seed/parameters, reference/mode, quality checks and creation time. Reuse `asset://clip/...` and playback. Project JSON contains adopted audio and necessary truthful generation metadata; full candidate provenance, adoption records and project revisions remain in their own metadata layers. Existing DSL seed/model fields are not evidence of actual runtime parameters.

Generate one candidate per action and accumulate alternatives through Regenerate. Retain the old limit of 12 unadopted candidates per clip, asking for a discard when full. Do not automatically delete WAVs in the first slice; projects and safety versions may still reference them. Changing reference selection leaves prior candidates comparable. Changed text prevents silently applying candidates generated for different content.

The old candidate schema/store requires `asset://candidate/...`. Unifying with clip assets requires coordinated schema, storage validation and playback mapping changes. Handle old manifests through explicit version detection and compatible reads; do not load them as the new format or rewrite the prototype runtime directory.

Adoption is one consistent state operation: validate project/clip/content identity, create a safety revision, record the original asset and timeline delta for undo, apply the new asset/actual duration/truthful engine information, then mark the mix stale. Do not report success after a persistence failure. Extend underestimated voice clips and shift following timing and associated emotion points. Reuse current Planner timing logic and cover non-Planner voice without clipping speech. Keep the planned window for shorter audio in the first slice so user-authored silence is not automatically compressed.

Undo restores asset, duration and timeline changes caused by adoption, respecting Planner-source boundaries. Persist recovery records with the project library so refresh does not lose recovery. If later edits invalidate quick undo, do not overwrite them with an old snapshot: disable that shortcut and expose the existing version recovery path. Persisted project state determines adoption status; a separate manifest flag cannot alone prove adoption.

Cancellation, failure, stale requests, text edits during generation and project switching must leave the original audio and mix freshness unchanged. Connect request AbortSignal to process termination while retaining independent client protection against late results. A generated but unadopted file is not a project content change.

## Selected long-text mode (technically verified, 2026-09-09)

Follow the selected recipe in `docs/AI_HANDOFF.md`: each non-final semantic group begins the remaining long text; generate the full continuation and safely extract that opening group. Generate the last group as a true ending. Retiming affects semantic-group joins only, preserving natural internal pauses. Optional DeepSeek analysis supplies short/medium/long classes; milliseconds come from equally weighted neighboring group means, then valid same-class samples, then 180/350/600 ms defaults. Preserve free local grouping and default-pause fallbacks. Adjust overall loudness once after group selection.

Padding decision (2026-09-08): the user explicitly chose to keep fixed neutral continuation padding, recalling that earlier long generations became faster and sharper toward the end. Default non-final input is the target group + remaining source text + padding needed to preserve the long-input setup. Generate the full input and retain only the target opening; padding never enters the final script/audio. Generate the final group independently with no padding. Keep this successful combined recipe without a padding-removal experiment as a prerequisite or follow-up task. Its isolated contribution is untested. The old 16-clause / 177–196-character construction is a reproduction baseline, not a hard limit for new scripts; do not truncate source text to fit it.

The accepted sample's manual group-5 replacement, cut overrides and specific seeds/step caps cannot become a generic service unchanged. Validate safe extraction, text coverage, intact word edges, breath/noise and voice identity across different texts. When a safe cut cannot be found, preserve the original project audio and existing candidates, record the failed take on the server and regenerate instead of silently clipping speech or presenting it as an accepted candidate. Feedback on the full-clause 01/02 pause comparison was received on 2026-09-08: the user had previously listened and noticed no clear difference between original pauses and class defaults; the actual listening date is unknown. No new winner was selected, so the class-local group-join preference remains unchanged. The comparison is no longer pending; the feedback does not confirm intact word edges or complete equivalence.

Current implementation contracts:

- `generationMode: "long_text"` adds optional `analysisProvider: "local" | "api"`; GPT/non-voice and direct-clip requests remain compatible. The workbench exposes “长文分组” and an analysis-source selector, generation progress/cancel, whole-candidate playback and expandable group playback/regeneration. Details such as seeds, padding and measured pause provenance remain optional disclosures.
- The input limit is 1–500 characters including punctuation, with at most 12 contiguous semantic groups. Every source clause must appear once in original order. The service does not shrink new scripts to the old 177–196-character sample: it retains the whole source suffix, adds continuation punctuation and as much fixed padding as fits, and reports an error when required source input exceeds the 500-character CLI limit. Only padding may be limited to fit; source text is never silently truncated. Non-final contexts aim to reproduce the accepted 16-clause construction where capacity permits. Final groups receive no padding and end naturally.
- Local Ollama supplies the default semantic plan and all clause-boundary pause classes. An explicitly selected external API reuses the existing Planner JSON-mode settings and sends the current spoken text; no audio is sent to it. A failed/invalid model plan falls back to an explicitly identified local punctuation/rule plan. Cancellation never triggers this fallback. This preserves a free local path without labeling rule output as LLM analysis.
- Each group is generated serially, verified through local ASR, and cropped only at a sufficiently quiet region with at least 80 ms word guards. Extracted output receives another ASR check for complete target text, missing/repeated speech and unwanted continuation. Uncertain source-word boundaries have no duration guess or sample-specific override. There are at most **three total attempts per group** (initial take plus two automatic retries); configuration, timeout, cancellation and unconfirmed-exit failures are not retried as new seeds.
- Coarse word timestamps can incorrectly assign an actual pause to the following word. The bounded refinement searches from 0.5 seconds before the earlier coarse edge to 0.65 seconds after the later edge, tests at most three nearby quiet candidates, and requires at least 80 ms of measured quiet on each side. Independent ASR must recognize the full left target and the full right continuation opening; missing first syllables, left-tail leakage or a one-sided-only match fail. The final cropped output is checked again. This repairs timing uncertainty without importing a manual sample cut or lowering text coverage and 80 ms timing protection.
- Quiet detection first uses the strict threshold `max(-68 dBFS, peak-frame RMS - 40 dB)`. When needed, a bounded fallback uses `min(-60 dBFS, peak-frame RMS - 30 dB, local 20th-percentile floor + 6 dB)` only if it exceeds the strict threshold. Strict and adapted candidates share the three-candidate budget; duplicate nearby cuts are not retried. Both retain 80 ms protection on each side and all independent ASR checks. The verified interval and threshold are recorded as optional server `cutValidation`; only its intersection reaching the final cropped edge contributes to trailing quiet. This retained amount is deducted at assembly, with at most one 10 ms fade within verified quiet. Leading quiet and the selected internal word-gap algorithm are unchanged.
- Internal pauses are measured adjacent ASR word gaps, rounded to 1 ms. Recording metadata accepts finite nonnegative gaps up to10000ms after target-word timestamps have been validated; a longer natural pause alone does not reject otherwise verified target speech. Preserve the original audio and measured value without shortening or retiming it. Preserve the existing−1e-6ms numerical tolerance: tiny floating-point overlap within that tolerance rounds to zero. Larger negative/nonfinite/over-limit gaps or unresolvable boundaries still fail. The unchanged join recipe uses only0–1200ms samples, retaining zero in a group's mean and excluding longer recorded pauses. Short/medium/long ranges are120–260 /261–480 /481–900ms. Join selection uses the equal mean of neighboring eligible group means if it belongs to the requested class; otherwise it uses eligible measured internal boundaries whose analyzed class and duration both match, then the class default180/350/600ms. Selected values are rounded to10ms. No per-character or speaking-rate formula is used. This recording-versus-sampling distinction was repaired on2026-10-07 after an exact target with a natural1.48-second source ASR gap was rejected by the old combined1200ms check.
- Group audio and its internal timing are preserved. Joins insert only the remaining silence after counting retained trailing/leading quiet; a naturally longer safe edge is preserved instead of cutting speech to force the target. The complete result receives one active-RMS adjustment toward −27 dBFS with a −1 dBFS peak limit. All group assets and assembly metadata remain outside Project JSON.
- Regenerating a selected group uses the original candidate's plan and other verified group assets, produces a new complete candidate, and recomputes affected joins/whole-result normalization. It does not mutate or automatically adopt the original candidate. Ownership, content/options and asset availability are checked before reuse; existing adopt/undo and timeline rules still apply.
- A runtime reservation spans planning, all TTS takes and CPU ASR. A native take and an ASR process each have a five-minute timeout; the full long-text job has a thirty-minute limit. Cancellation aborts the active process and waits for confirmed exit before releasing the lock. Unconfirmed exit keeps the lock and working directory, preventing a second TTS run. Server evidence lives under `voxcpm2-product/long-text/<run-id>`; ASR temporary files use `voxcpm2-product/analysis-runs`.
