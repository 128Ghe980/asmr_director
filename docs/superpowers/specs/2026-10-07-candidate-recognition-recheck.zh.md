# 候选音频重新识别

日期：2026-10-07

在候选的「采用 / 放弃」旁加入 **重新识别**。读取该候选已保存的完整原始录音，按当前离线 ASR 与裁切规则重新检查；不调用 TTS，不改变声音设置或种子，不自动采用。

候选须有长文计划及可精确追溯的原音。服务端核对归属、ready 状态与当前台词/上下文指纹；过期候选或原音缺失、映射歧义时保留历史并报错。逐组按已记录素材及对应 trace 结果查原音，局部重生成复用的组可来自旧 trace；不能按相同文本选择最新录音，也不能用裁过的组素材替代完整原音。

POST `/api/audio-candidates/[candidateId]/recheck` 接收 `{project, clipId}`，返回 `{candidate}`。复用原生运行互斥及有超时、可取消的串行 ASR，使用已有停顿/响度规则重新组装。另存新候选和 trace，保留重复识别需要的原音链路；重算识别警告、保留其他生成警告。裁切仍无法确认时可按既有检查协议保留完整原音供复核；致命错误、取消及超时不能替换旧候选或修改工程。

界面显示进度和取消，阻止冲突的生成/参考导入，切换工程、片段或卸载时中断，并忽略迟到结果。只增加新候选，是否采用由用户决定。不支持或过期的候选显示禁用原因。

验证覆盖归属/指纹、精确原音关联、重复识别、零 TTS、取消/失败保留及界面切换竞态；构建及浏览器验证包含用户原音的一次真实重检、旧记录保护与紧凑按钮行。仍属于音质 V1，SFX 暂停。

交付验证：136项定向测试、完整TypeScript、相关ESLint及正式构建；真实UI取消及5.05秒/100%成功重检、刷新和390px紧凑布局通过。完整证据与历史支持范围见 [开发记录](../../records/2026-10-07-audio-quality-v1-candidate-recheck.md)。
