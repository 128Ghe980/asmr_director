# 裁片识别的保守发音容错

日期：2026-10-07。[English version](2026-10-07-voice-recognition-phonetic-tolerance.md)。

本项扩展音质 V1 的既有语音裁切检查，不新增顶层路线，SFX 暂停状态保持。它补充 [有界文字容错](2026-09-23-tolerant-voice-extraction.zh.md)，沿用 [候选重新识别](2026-10-07-candidate-recognition-recheck.zh.md) 流程。

## 问题与范围

目标 `来~~，面来啦！汤也喝一点，暖胃。` 归一后为 11 字。完整原音识别前缀 `来,面来了,汤也喝一点,暖胃。` 只有一字替换，满足原有 90% 规则；裁片识别 `来,面来了,糖也喝一点,暖胃` 有两字替换，文字相似度 81.8182%，即使可能只是识别误差，仍被原规则拒绝。

增加本地、有界的拼音补充分支，仅用于独立核对后的目标裁片，即 **crop-only**。不能用拼音寻找原音终点，也不能向后扫描另一句相似台词。保留普通 90% 同位替换路径，以及已有边界证据限定的 85% 有界编辑路径；先尝试这两条，失败后才尝试新模式。发音容错的原音目标前缀必须已经通过原 90% 比较、结束于完整 ASR 词边界，且完整原音转录与源词列表拼接前缀相符。

## 文字与发音规则

沿用 Python 现有归一：繁转简、忽略标点和空白、转小写、`地`/`得` 等价为 `的`。波浪号及中英文标点均不计入台词字数。设归一后的目标长度为 `N`；目标与裁片必须等长、`N >= 10`，仅允许一至两处同位置、有序字替换。不能插字、漏字、移位、交换、新增重复短语或出现三处字差。变化位置必须是单个汉字；数字与否定字受保护。近声母或近韵母不放行。

使用整段文字的 `pypinyin` 数字声调结果，仅允许以下规则：

| 规则 | 必须具备的证据 | 罚分 |
| --- | --- | --- |
| `same_tone` | 音节与声调完全相同 | 0 |
| `source_supported_tone` | 音节相同、声调不同；完整原音对应位置识别为目标字 | 0.25 |
| `sentence_particle` | 仅原始请求子句末的轻声 `啦 (la5)` ↔ `了 (le5)` | 0.25 |

至多允许一处 `source_supported_tone`，其源字须能由完整归一前缀 `sourcePrefix` 在相同位置追溯。句末读 `liao3` 的 `了` 不属于轻声语气词规则。

要求 `phoneticSimilarity = 1 - 罚分总和 / N >= 0.95`，内部使用四分之一罚分的整数比较，避免阈值舍入误差。这是 **文字拼音的加权规则得分**，不是声学指标、置信概率或语义正确证明。同音同调汉字仍可能表达不同意思，用户需要试听。

本例 `啦 → 了` 位于子句末；`汤 (tang1) → 糖 (tang2)` 的原音对应字为 `汤`，具备源支持。文字相似度保留 `0.818182`，拼音得分为 `1 - 0.5 / 11 = 0.954545`。

## 声学边界与完整性要求

每个成功的拼音容错裁片必须具备真实 `cutValidation`：附近实测至少 160ms 的静音区间，切点两侧分别至少 80ms。噪声底门槛、原音时长边界、词时间戳验证和候选切点次数上限保持。字数或拼音不能替代缺失的声学边界。

分别独立识别目标侧、后文侧及最终处理后的裁片。目标侧与最终裁片的整段文字，须与词列表拼接结果在归一后完全一致；后文仍须严格匹配开头及内容。原音前缀完全匹配、走快速裁片后才出现拼音差异时，必须回到既有双侧验证，再检查最终裁片。没有真实切点证据不能发布拼音容错结果。

子句须覆盖完整目标，各子句边界须落在完整 ASR 词末。实测内部停顿及原有边缘处理保持；拼音不能在一个词内部虚构子句边界。没有后文时不开启本分支；后文首 `嗯` 的衔接桥接也不开启，桥接目标仍要求精确匹配。

## 结果、界面与兼容

新比较使用 `mode: phonetic_substitutions`、`status: different`。保留真实文字 `similarity`、`threshold: 0.9`、`substitutionCount` 和归一的 `expected`、`recognized`；追加 `phoneticSimilarity`、`phoneticThreshold: 0.95`、`sourcePrefix`，以及按顺序包含字索引、目标字、识别字、数字声调拼音和规则的差异证据。仅语气词携带 `clauseEnd: true`；仅源支持声调差携带 `sourceCharacter`。

Python 重算公开得分并核对源前缀出处。TypeScript 检查长度、有序字差、罚分、对应源字、源词列表与完整原音转录、目标转录、请求子句末、识别完成状态及真实静音切点。只有这些额外护栏全部满足，才允许文字覆盖率低于 90%，最低为本规则数学上可能的 80%；普通路径门槛保持。TypeScript 未复刻 Python 的完整 OpenCC 转换；遇到繁简归一无法与原始证据对齐时，保守拒绝新模式，不能放松出处检查。

界面同时展示文字相似度与拼音容错得分，列出差异证据，提示 `已截取目标片段；拼音容错通过，请试听。` 保留试听警告和手动「采用」，不自动采用或替换已有候选。用户可在支持的旧候选旁点击 **重新识别**，用已保存的完整原音应用新规则；另加新结果，保留旧候选、原音及来源链路。本规则不会触发 TTS 重生成。

`pypinyin` 为可选依赖；缺少词典或查词异常时，保留普通比较及已有的保守拒绝/完整原音复核流程，不能导致 ASR 工作进程整体不可用。没有新字段的旧元数据继续有效。
