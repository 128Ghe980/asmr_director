# 项目结构升级设计

日期：2026-06-17

## 背景

这个项目已经从单个 demo 页面，成长为一个本地优先的 ASMR 导演工作台：

- 应用可以通过分镜、时间线和检查器编辑 Timeline DSL。
- 项目 JSON 可以导入、导出、重置、从本地存储恢复，并进行校验。
- 界面已经改成中文优先。
- 当前项目级操作仍然分散在 `ProjectHeader` 和 `ProjectControls` 里。
- 页面还没有清楚地给未来项目列表、项目元数据和预览层预留位置。

之前路线里定义的这一步是更清楚的 Project Shell / 项目工作区结构：

- 明确区分当前项目、项目状态和本地保存状态。
- 把项目级操作整理得更像工作台。
- 给未来项目列表、项目元数据和预览层留位置。

最开始只做“顶部项目壳 + 工具栏”的解释不够，因为它没有明显留出项目列表、元数据区域和预览层。最终确认的方向是更完整的 **C+ 结构**。

## 已确认方向

采用 **C+：双侧可折叠的项目工作区**。

留档 mock：

- `docs/mockups/2026-06-17-project-structure-upgrade.html`
- `docs/mockups/2026-06-17-project-structure-upgrade-collapsible-c.html`

C+ 结构有四个区域：

1. **左侧项目轨**
   - 展示当前项目。
   - 明确给未来最近项目、项目列表等工作流留位置。
   - 可以折叠成窄轨，释放编辑空间。

2. **顶部工作区头部**
   - 展示项目身份和元数据摘要。
   - 展示项目状态、校验状态和本地保存状态。
   - 承载项目级操作：`导出`、`载入`、`重置`。

3. **中间编辑工作区**
   - 保留当前核心工作流：分镜、时间线 / 情绪 / 校验、检查器。
   - 双侧展开时，中间仍然必须是最重要的区域。
   - 任意一侧折叠时，中间区域随之扩展。

4. **右侧项目详情栏**
   - 包含三个项目级区块：
     - 预览层占位。
     - 项目元数据。
     - 保存 / 校验摘要。
   - 作为一个整体侧栏折叠，以释放编辑空间。

这样能让应用更像一个持久项目工作区，同时不引入后端持久化、登录、协作、真实生成或完整多项目管理。

## 目标

- 让页面看起来像项目工作区，而不是单个内嵌 demo。
- 在工作区层面清楚展示当前项目身份、保存状态和校验状态。
- 把项目级操作从编辑流程中间移出来。
- 给未来项目列表、元数据和预览功能提供稳定布局位置。
- 允许用户在需要专注编辑时折叠左右两侧区域。

## 非目标

- 不做后端持久化。
- 不做登录。
- 不做协作。
- 不做完整多项目 store。
- 不做真实音频 / 图片生成。
- 不做真实预览播放或资产渲染。
- 不做破坏性的 schema 重设计。

## 用户体验

默认状态：

- 左侧项目轨展开。
- 右侧项目详情栏展开。
- 顶部展示项目名、时长、语言、版本或项目 id、编辑状态、本地保存状态和校验摘要。
- 在常规桌面宽度下，中间工作区仍然可用，并且不产生页面级横向滚动。

专注编辑状态：

- 用户可以折叠左侧项目轨。
- 用户可以折叠右侧项目详情栏。
- `专注编辑` 操作可以一次折叠两侧。
- 折叠后的侧边区域仍然保留窄轨或标签，方便用户恢复，不会迷路。

移动端行为：

- 侧边区域改为堆叠，不强行制造横向溢出。
- 折叠控制仍然可触达。
- 项目级按钮保持简短清晰。

## 组件设计

围绕明确的工作区边界新增或重塑组件：

- `ProjectWorkspace`
  - 负责顶层 shell 布局。
  - 从 `StudioApp` 接收项目、校验摘要、本地保存状态和操作 handler。
  - 用本地 UI state 控制左侧 / 右侧折叠状态。

- `ProjectRail`
  - 展示当前项目身份。
  - 展示最近项目、项目列表等轻量未来占位。
  - 暂不实现真实多项目持久化。

- `ProjectWorkspaceHeader`
  - 展示当前项目摘要、校验摘要和本地保存状态。
  - 承载项目操作：导出、导入 / 载入、重置。
  - 可以用紧凑区域展示或委托 JSON 导入文本区。

- `ProjectDetailsDock`
  - 展示预览层占位、项目元数据、保存 / 校验摘要。
  - 作为一个整体折叠。

- 现有编辑面板
  - `StoryboardPanel`、`TimelinePanel`、`ValidationPanel` 和 `ClipInspector` 继续专注编辑。
  - 它们不再拥有项目级导入、导出、重置 UI。

`StudioApp` 仍然是当前 `AsmrProject`、选中 clip、dirty / restored 状态、本地持久化、导入 / 导出、重置和校验的唯一状态拥有者。

## 派生数据

新增一个小型纯函数模块，例如 `project-summary.ts`。

它从以下输入派生展示数据：

- `AsmrProject`
- dirty / restored / local persistence 状态
- validation issues

它输出：

- 项目身份标签。
- 项目元数据行。
- 本地保存状态标签。
- 校验状态标签和问题数量。
- 预览占位状态。

这个 helper 不修改项目，也不依赖 React。

## 交互规则

- `导出` 行为保持不变，导出当前项目 JSON。
- `载入` 行为保持不变，继续处理 JSON 解析和 schema 错误。
- `重置` 行为保持不变，恢复 demo 项目。
- 折叠侧边区域只改变布局，不改变项目数据、选中项、校验或本地持久化。
- `专注编辑` 切换两侧：
  - 只要任意一侧展开，就同时折叠两侧。
  - 如果两侧都已折叠，就同时恢复两侧。
- 折叠状态默认只在当前浏览器会话内保存；除非实现非常独立且简单，否则不要把布局偏好持久化。项目数据持久化比布局偏好更重要。

## 错误处理

- 现有导入解析 / schema 错误仍然显示在导入区域附近。
- 校验问题仍然显示在 Validation Panel 和字段级高亮里。
- 工作区级校验只展示问题数量和状态摘要，不替代详细校验。
- 预览未实现时，预览区显示中性的 `未生成`，不要显示成错误状态。

## 测试

单元测试：

- 为 project summary helper 增加测试。
- 覆盖干净 demo 状态、已编辑状态、已恢复 / 本地状态、校验通过、校验失败数量。
- 确认预览占位状态稳定。

UI / 浏览器验证：

- 桌面默认布局显示左侧项目轨、顶部工作区头部、中间编辑区和右侧详情栏。
- `专注编辑` 能折叠两侧并扩大中间工作区。
- 左右折叠控制可以独立工作。
- 导入、导出、重置移动位置后仍然可用。
- 当 schema 错误存在时，校验摘要会更新。
- 桌面和移动端宽度都不能产生页面级横向溢出。

## 实现约束

- 保持当前本地优先的单项目模型。
- 保持 schema 和导出的 JSON 格式不变。
- 可见按钮名保持简短中文。
- 视觉方向继续贴合现有 Studio Console：专业工具优先，ASMR 氛围克制存在。
- 暂不实现完整项目列表；这一步只需要占位。
- 暂不实现真实预览生成；只预留预览层。

## 验收标准

- 应用拥有可识别的 Project Shell：左侧项目轨、顶部状态头部、中间编辑区、右侧项目详情栏。
- 左侧项目轨和右侧项目详情栏都可以折叠。
- `专注编辑` 可以同时折叠两侧。
- 项目级操作不再散落在编辑器中间。
- 现有编辑、校验、持久化、导入、导出和重置行为仍然可用。
- mock 留档和中英文 spec 都已提交，方便未来 AI 接手和上下文压缩后恢复理解。
