## 范围与目录

用户要求新增美观的批量下载入口，将已经生成并接受的全部音频放进一个目录，并区分无后处理和环绕等后处理版本。

下载使用当前工程快照，只选择时间线中 `generation.status: asset_generated` 且 `asset://clip/<asset_id>` 一致的当前素材。人声、呼吸、音效及环境片段均可纳入；未采用候选、完整生成窗口录音、历史版本和整段混音不纳入。下载不触发生成或采用，也不修改工程。

一个 ZIP 内是经过安全处理的工程名称目录，下设 `无后处理/`、`后处理/` 与 `导出清单.json`。片段按时间线开始顺序编号，两版本使用相同编号 WAV 文件名。中文名称使用 UTF-8；标题及片段名称不能造成嵌套路径、目录穿越或 Windows 保留文件名。清单对应片段/素材 ID 与两个路径，并记录来源设置、处理模式、空间状态及后处理时长。

## 音频行为

`无后处理` 逐字节保留已采用 WAV 的完整内容。这里指当前采用的素材，本身可能已经是截取候选；不能擅自替换为更早的完整生成窗口。

`后处理` 复用现有片段处理流程及当前音量、淡入淡出、位置设置。保留完整源时长，不按时间线裁短、循环重复、填入工程起始静音或下个片段前的等待。输出独立的 48 kHz 双声道 PCM16 WAV；不逐片段应用工程主响度归一或整段混音限幅。

工程双耳开关开启时，单声道人声使用已认可的原 D 距离、房间及移动处理，完整保留 650 ms 房间尾声；空间处理后应用片段音量，淡入淡出沿用 D 原有处理。D 若回退为未处理单声道，整包明确报错，不能冒充已完成空间处理。已有立体声保留原双声道并应用普通音量/淡入淡出，清单标记为立体声来源，不宣称新生成环绕。非人声及双耳关闭时的人声，使用现有适用的 PCM 音量、淡入淡出、声像、距离与移动处理。

## 界面与交付

工程顶部新增克制的绿色下载入口及已采用数量。紧凑弹层预览双文件夹，说明当前空间开关，并覆盖空状态、准备中、取消、可重试错误和已发起下载状态。保持一屏工作区；小屏使用有无障碍名称的图标入口，弹层受视口限制且内部滚动。Escape、外部点击、键盘焦点及读屏标签可用。

`POST /api/assets/batch-download` 校验工程并先准备完整临时 ZIP，再返回文件流，缺失素材或处理失败仍返回可读 JSON 错误。按片段顺序处理，原声流式写入不压缩 ZIP；每个服务进程同一时间只准备一包。限制为 2,000 段、单源 128 MiB、单段 10 分钟及整包 1 GiB。取消传递到素材读取和空间处理；失败/取消和响应流结束均只清理本次生成的临时目录。新临时文件沿用既有 I 盘空间缓存配置，可通过 `ASMR_BATCH_DOWNLOAD_TEMP_ROOT` 指定。

前端现发送`Accept: application/json`，POST返回`{ downloadUrl, filename, clipCount, size }`，浏览器通过`GET /api/assets/batch-download?token=<UUID>`直接下载ZIP，不再读取二进制Blob。默认POST仍保留原ZIP及attachment响应。UUID链接仅在当前进程有效、单次领取、5分钟过期，最多保留2个待下载包；不公开或接受文件路径。GET先领取，再打开/检查文件后返回头部，以64KiB字节背压传输，完成/取消/打开失败只清理一次；放弃链接自动过期，重启需重新打包。音频与目录行为保持。
