## 目标与入口

工程台词编辑区增加「音频」「分镜」两个紧凑组，各含「全部生成」「全部重生成」及目标数量。保持现有一屏工作区，由分组说明明确区分补齐缺项与全部重新生成。

| 模式 | 目标及保留规则 |
| --- | --- |
| `audio_missing` | 处理非空人声中缺少已生成/采用音频的片段；只有状态为`asset_generated`且素材ID/URI均非空才算已有采用而跳过。 |
| `audio_all` | 按当前引擎与声音设置重生成全部符合条件的非空人声。VoxCPM2生成新候选，旧采用音频留到手动采用；GPT-SoVITS沿用直接提交新素材的既有行为。 |
| `storyboard_missing` | 只处理已采用本地音频且没有保存分镜的人声片段；任何已有分镜都跳过，包括过期或未填完的手改内容。 |
| `storyboard_all` | 重新生成全部符合条件、已采用本地音频的人声分镜；每项有效结果被接受后才替换原分镜，失败或取消保留原说明。 |

音频批量复用各引擎已有流程与当前声音设置。候选/人工采用保证只适用于VoxCPM2；GPT-SoVITS的`succeeded`更新继续直接提交生成素材。批量不生成整段混音。分镜必须绑定已生成本地素材，URI严格匹配`asset://clip/<assetId>`，复用逐段接口、工程原台词、实际采用WAV及实测时长；只生成文字提示词，不调用H3成片或生成新音频。

## 队列与写入保护

启动时固定目标列表，每次只处理一项，等终态后再开始下一项。发送与接受结果前都读取最新工程，重新核对该项资格及来源；运行中新增的片段不扩展本轮目标。

界面显示当前操作、已处理/总数及成功、跳过、失败数量。单项失败记录后继续后续项目，已成功结果保留。没有目标时显示数量零且按钮禁用，不发生成请求。取消中止当前请求、不再派发下一项，并保留已完成结果。

存储致命错误为例外：HTTP 507 / `INSUFFICIENT_STORAGE`停止队列，保留已完成结果，提示致命原因及未处理数量。WAV原子发布与运行存储恢复见 [故障记录](../../records/2026-10-02-audio-quality-v1-storage-recovery.md)；其最新运行检查点覆盖下方较早验收快照。

队列身份与工程身份共同保护写入。切换工程、卸载或相关来源变化使旧工作失效，迟到响应不能写入其他工程或已变更片段。音频沿用适用的生成上下文校验；分镜保留场景、台词、采用素材、保存内容编辑身份、当前模式及前镜依赖。补缺与重生均使用每段保存的下一次生成模式；连续镜头需要相邻可用前镜，否则该项失败并保留旧说明，新镜头有可用前镜时参考，无前镜时允许仅按背景生成。批量与手动单段分镜请求互斥，运行中锁定分镜、背景及偏好编辑。

桥接启动Promise不能通用地代表生成完成，应由candidate/succeeded/failed/canceled终态更新结束当前队列项。启动被禁用、请求失败及取消也必须结束等待，避免队列卡住。
