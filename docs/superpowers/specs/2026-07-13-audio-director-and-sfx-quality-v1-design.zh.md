# 人声导演与真实 ASMR 音效质量 V1 设计

日期：2026-07-13

状态：对话中的设计内容已逐项确认，等待用户审阅书面版本；尚未开始实施。

## 1. 顶层决定

下一阶段不再增加工作台外壳，直接解决“生成出来的声音不好听”这个核心问题，包含两条主线：

1. 让导演动作真正改变人声和音效，而不是只修改 JSON、音量或普通声像。
2. 扩大 ASMR 音效种类并提高质量，不再只依赖当前有限的程序噪声。

声音来源采用已经确认的免费混合方案：

- 免费且授权清楚的音效素材；
- 免费的本地 AI 音效生成；
- 现有程序合成作为明确标注的基础候选和兜底；
- 暂缓付费 API、付费素材库和需要用户自行录制的方案。

## 2. 当前问题

- `更柔` 主要修改风格字段并降低音量，没有生成真正更柔的人声。
- `更近`、`更远` 和左右位置主要依赖 gain / pan，缺少可信的贴耳、前后和上下听感。
- `停顿` 只是追加文本标记，不是可控的自然停顿。
- 呼吸、摩擦、敲击和环境声种类少，当前程序合成无法覆盖最初设计中的真实材质和动作。
- 用户不能方便地比较原版、多个候选和不同来源，也不能明确采用或撤回某个结果。

本阶段的完成标准是“能听出真实差别”，不是“成功生成一个 WAV 文件”。

## 3. 目标

- 完成可听、可比较、可撤回的人声表演和空间导演动作。
- 让同一套空间动作可以用于人声、呼吸、摩擦、敲击等音效。
- 提供完整水平环绕、两种完整垂直环绕和左右单侧运动。
- 为所有环绕提供正向/反向、持续时间和圈数控制；速度由圈数与持续时间共同决定。
- 默认直接使用一套空间听感方案；用户觉得前后或上下不准确时，再试听并切换其他方案。
- 首批覆盖 8 类高频 ASMR 音效。
- 免费素材、本地 AI 和程序合成产生的候选可以直接比较。
- 原声音始终保留，采用新版本后仍可恢复。

## 4. 本阶段不做

- 付费音效或语音 API。
- 付费素材库。
- 要求用户自行录音。
- 训练平台、数据集清洗平台或模型市场。
- 完整 DAW。
- 云账号、计费、协作和发布系统。
- 在没有听感验收的情况下接入大量模型。

## 5. 用户使用流程

1. 用户选中一个人声或音效 Clip。
2. 用户选择人声表演动作、空间动作，或者新的音效来源。
3. 系统生成一个或多个新候选，不覆盖当前声音。
4. 用户可以连续播放原版与候选，也可以比较免费素材、本地 AI 和程序合成版本。
5. 用户采用其中一个候选，或者放弃并继续使用原版。
6. 采用结果后重新生成整段混音。

候选必须显示来源和执行方式，例如“免费素材”“本地 AI”“基础合成”“人声重生成”“空间处理”。

## 6. 导演动作

### 6.1 人声表演动作

#### 更柔

- 目标是更轻、更柔、更接近耳语的真实表演变化。
- 通过本地语音模型重新生成多个候选。
- 仅降低音量不算完成，也不能标记为“更柔”。
- 当前 GPT-SoVITS 继续作为基线；如果不能稳定产生可听差异，就只能作为不支持该动作的 provider，不能伪装成功。

#### 停顿

- 用户选择句子中的停顿位置和停顿时间。
- 系统只重新生成受影响的句子或短语。
- 停顿必须进入可重现的结构化设置，不再只在文本末尾追加省略号。

### 6.2 人声与音效共用的空间动作

- `更近`
- `更远`
- `左耳`
- `右耳`
- 完整水平环绕
- 前后垂直环绕
- 左右垂直环绕
- 左侧水平运动
- 右侧水平运动
- 左侧垂直运动
- 右侧垂直运动

### 6.3 运动路径

- 完整水平正向：前 → 右 → 后 → 左 → 前；反向走相反顺序。
- 前后垂直正向：上 → 前 → 下 → 后 → 上；反向走相反顺序。
- 左右垂直正向：左 → 上 → 右 → 下 → 左；反向走相反顺序。
- 左侧水平：左前与左后之间经过左耳区域移动；反向交换起止方向。
- 右侧水平：右前与右后之间经过右耳区域移动；反向交换起止方向。
- 左侧垂直：左上、左耳和左下之间移动；反向交换起止方向。
- 右侧垂直：右上、右耳和右下之间移动；反向交换起止方向。

每个运动设置保存：

- 路径；
- 正向或反向；
- 开始时间；
- 持续时间；
- 圈数。

速度由“圈数 ÷ 持续时间”得到，避免同时保存三个互相冲突的数值。界面仍可显示和调整速度，改变速度时同步更新圈数或持续时间。

### 6.4 空间听感方案

- 系统提供一个开箱即用的默认方案，用户无需先校准。
- 设置中提供多个备选方案，并提供上、下、前、后、左、右测试音。
- 用户只有在默认效果不准确时才需要调整。
- 用户选择后保存为项目默认方案。
- 所有空间预览明确提示使用耳机。

### 6.5 动作组合

人声表演动作先产生新的人声候选，空间动作再作用于被选中的声音。例如：

- 更柔 + 更近；
- 更柔 + 右侧垂直运动；
- 敲击 + 水平反向环绕；
- 呼吸 + 左侧由上向下移动。

## 7. ASMR 音效来源

### 7.1 免费授权素材

- 只使用许可证和来源清楚的免费素材。
- 每个素材保存原始页面、作者、许可证、是否需要署名和是否允许重新分发。
- 不允许重新分发的素材不能直接打包进项目仓库或安装包。
- 素材缺少许可证信息时禁止进入正式候选。

### 7.2 本地 AI 生成

- 至少接入一个可以在本机运行的免费本地音效模型，作为可试听的实验来源。
- 选型必须在用户当前 Windows 与 RTX 3060 Laptop 6GB 环境验证。
- 同一描述可以生成多个候选。
- 本地生成质量不够时仍可供比较，但不能自动成为默认结果。
- 模型代码、权重和生成物继续保存在 D 盘 runtime，不提交进项目仓库。

### 7.3 程序合成

- 保留现有程序合成，界面标注为“基础合成”。
- 它可以由用户直接选择，也可以在素材缺失、本地模型失败、显存不足或需要立即预览时兜底。
- 雨声、房间底噪等适合程序合成的声音可以正式采用，只要用户试听后认可。
- 系统不得把基础合成自动描述成真实录音或高质量 AI 音效。

### 7.4 首批 8 类音效

1. 雨声；
2. 房间底噪；
3. 轻呼吸；
4. 被子摩擦；
5. 衣物摩擦；
6. 翻书；
7. 指尖轻敲；
8. 轻笑或气声。

每个素材或生成结果至少记录：类别、材质、动作、强度、距离、声道、时长、是否可循环、来源和许可证。

## 8. 工程结构

### 8.1 原声音与候选

当前 `AsmrProject` 继续保存用户已经采用的 Clip 资产。所有未采用候选和操作历史放在独立的本地候选目录与清单中，避免把大量 provider 细节写进 Timeline DSL。

每个候选至少记录：

- candidate ID；
- project ID 与 clip ID；
- 原始资产 ID；
- 来源类型；
- provider 与版本；
- 实际使用的 seed 和配置摘要；
- WAV 的真实时长、采样率和声道；
- 许可证信息；
- 生成时间；
- 应用的导演动作；
- 自动检查结果；
- 是否已采用。

采用新的人声或音效候选时，只切换当前 Clip 的原始声音引用；采用空间动作时，保留原始声音引用，只保存空间设置。原资产、预览缓存和其他候选继续保留。候选数量需要设置上限，并提供安全清理未引用资产的能力。

### 8.2 可重现的空间设置

空间运动属于产品级导演信息，需要进入 Project JSON，而不是只存在于浏览器临时状态。

为 Clip 增加可选的、与具体模型无关的 `spatial_motion` 设置：

- path；
- direction；
- start_offset；
- duration；
- cycles；
- profile_id。

旧项目没有该字段时继续按当前静态 position 工作。项目导入和本地项目库负责兼容迁移。

### 8.3 干声音规则

- 生成或导入的原始声音不预先烘焙 Timeline 音量、淡入淡出和空间运动。
- 音量、淡入淡出和空间处理只在预览或项目混音阶段应用一次。
- 这条规则同时适用于人声、素材库音效、本地 AI 音效和程序合成。
- 所有输入先转换为统一的内部音频格式，再参与空间处理和混音。
- 内部混音默认使用 48 kHz stereo float；32 kHz TTS 和其他采样率在进入混音前重采样。
- 真实 stereo 或 binaural 来源必须有保留策略，不能一律折叠成 mono。

### 8.4 空间处理

完整环绕和垂直运动不能只使用左右音量差。空间处理至少包含：

- 与方向和距离相关的频率变化；
- 左右耳之间的细微时间与音量差；
- 早期反射和少量房间感；
- 使用开放授权的双耳空间数据模拟前后和上下方向；
- 连续路径插值，避免位置突然跳变。

默认与备选空间数据的来源、版本和许可证必须记录在 `docs/THIRD_PARTY_RUNTIMES.md`，只有允许使用和分发的数据才能进入产品。

## 9. 数据流程

### 新音效

1. 用户输入或选择音效描述。
2. 系统查找免费素材候选。
3. 用户可以同时要求本地 AI 生成候选。
4. 程序合成作为可选候选或失败兜底。
5. 所有候选转换为统一音频格式并生成真实技术信息。
6. 用户试听、比较并采用一个候选。
7. 采用结果写回当前 Clip，再进入空间动作和项目混音。

### 导演动作

1. 用户选择当前声音与动作。
2. `更柔`、`停顿`进入人声重生成；空间动作进入本地空间处理。
3. 系统生成可试听候选或预览缓存。
4. 用户比较原版与新版。
5. 采用人声重生成时切换声音资产；采用空间动作时只保存空间设置并继续引用原始干声音；撤回时恢复原资产或原空间设置。
6. 项目 mix 被标记为需要重新生成。

## 10. 本地模型验证

### 本地音效模型

实施的第一项研究任务使用衣物摩擦、指尖轻敲和雨声三个固定描述比较免费候选模型。选择条件：

- 许可证允许本项目使用；
- Windows 本地可以安装；
- RTX 3060 Laptop 6GB 可以完成生成，或者可通过明确的 CPU / 显存卸载模式完成；
- 输出可以转换为项目统一格式；
- 至少有一类声音达到可接受的听感；
- 不依赖付费接口。

最适合的一个模型作为首个本地 AI provider。即使它只在部分音效上表现较好，也可以作为实验候选来源；没有通过听感的类别继续使用免费素材或程序合成。

### 本地人声模型

- GPT-SoVITS 继续作为现有基线。
- 用固定中文近讲脚本验证它是否能通过参考声音或可控参数产生明显的“更柔”。
- 如果做不到，评估一个免费、可本地运行并更适合表演控制的语音 provider。
- 没有 provider 通过听感前，`更柔` 不得标记完成。

## 11. 错误与兜底

- 素材或生成失败时保留当前声音，不清空 Clip。
- 本地模型显存不足、超时或进程退出时显示明确原因，并允许改用程序合成或免费素材。
- 缺少许可证的素材不能采用或导出。
- 空间预览失败时继续播放原声音，不写入未完成设置。
- 环绕持续时间短于可用范围时提示用户调整持续时间、圈数或 Clip 长度。
- 默认空间方案听感不准确时，允许切换其他方案，不要求重新生成原声音。
- 删除候选前检查是否仍被当前项目、版本或其他候选引用。

## 12. 完成标准

### 听感

- `更柔`：原版与新版有明显表演差别，不只是音量差。
- `更近/更远`：能听出距离变化，而不是单纯大小声。
- 左右和环绕：戴耳机可以判断运动方向。
- 垂直环绕：默认方案产生基本上下运动感；不适合时可切换方案。
- 摩擦、翻书、敲击等能听出具体材质和动作。
- 雨声和房间底噪长时间播放没有明显循环接缝。
- 不出现爆音、突然断音或明显音量跳变。

### 产品行为

- 原版、候选和不同来源可以直接切换比较。
- 采用、撤回和重新混音行为稳定。
- 任何新操作不会覆盖原资产。
- 候选来源、许可证和执行方式清楚可见。
- 程序合成不会被误标为真实录音或 AI 高质量结果。

### 自动验证

- 检查真实 WAV 格式、时长、采样率、声道、峰值和削波。
- 检查空间路径连续，没有突然跳点。
- 检查单次音量和淡入淡出，避免重复处理。
- 检查候选操作不会覆盖原资产，采用与撤回可往返。
- 检查许可证必填字段和未授权阻塞。
- 修复当前独立 TypeScript 检查中的测试类型错误，并把 test、typecheck、lint、webpack build 合并为统一验证命令。
- 浏览器验证桌面与窄屏下的候选比较、导演动作、空间设置和失败兜底。

## 13. 交付顺序

### 第一轮：完整小样

固定使用一句人声、一段衣物摩擦、一段敲击和一段雨声，先完成：

- `更柔`；
- `更近/更远`；
- 完整水平环绕；
- 左右垂直环绕（左 → 上 → 右 → 下）；
- 免费素材、本地 AI、程序合成三种来源；
- 原版/候选比较；
- 采用、撤回和重新混音。

第一轮必须通过实际试听后才进入扩展。

### 第二轮：扩大完整能力

- `停顿`；
- 左耳、右耳；
- 两种完整垂直环绕；
- 左右两侧的水平和垂直运动；
- 所有运动的正反方向、持续时间、圈数和速度控制；
- 全部 8 类 ASMR 音效；
- 默认空间方案和备选方案。

### 第三轮：整段验收

使用一个完整 ASMR 项目检查人声表演、音效材质、空间方向、长时间环境声、人声遮挡、版本切换和最终混音质量。
