## 请求、候选与项目状态

扩展现有 `GenerateClipRequest`，增加经过服务端校验的 `voiceOptions`：provider、voicePackId、referenceMode、generationMode。`generation-bridge.ts`、本地 bridge、clip API、`local-clip-generation.ts` 使用同一请求与可辨识结果；旧 GPT 与非 voice 调用保持兼容。Vox 成功返回候选，不能走当前成功回调的立即替换路径。

候选 manifest 放在外部 runtime，包含 project/clip ID、目标文本和请求指纹、稳定资产 URI、WAV 格式/实际时长、引擎与模型/权重标识、实际 seed/参数、参考与模式、质量检查和创建时间。候选复用 `asset://clip/...` 及播放能力；Project JSON 只记录已采用音频和必要的真实 generation 信息。完整候选来源、采用记录和项目版本位于各自元数据层。旧 DSL seed/model 不可冒充真实运行参数。

每次生成一个候选，“再生成”可以积累多个供比较；沿用每片段最多 12 个未采用候选的上限，到达上限提示放弃候选。首版不自动删除 WAV，避免误删当前工程和安全版本引用的音频。用户改变参考选择后仍能比较已有候选；文本改变则已有候选不能无提示地套用到新文本。

旧候选 schema/store 强制使用 `asset://candidate/...`。统一为现有 clip 资产时，须同步适配 schema、存储校验与播放映射；旧 manifest 单独做版本识别和兼容读取，不直接当作新格式载入，也不改写原型运行目录。

采用必须作为一致的状态操作完成：检查项目/clip 和内容指纹 → 建立安全版本 → 保存原资产与时间线变化的撤回记录 → 写入新资产、实际时长与真实引擎信息 → 标记需重混。保存失败不得提示采用成功。音频超过规划长度时延长人声并顺延后续时间线及相关情绪控制点；复用当前 Planner 时长处理，并覆盖非 Planner 人声的无截词行为。短音频首版保留原规划窗口，避免自动压缩用户的留白。

撤回恢复采用造成的资产、时长和时间线变化，同时恢复相应策划来源边界。记录需随项目库保存，刷新后仍能恢复。若采用后又编辑了项目，禁止用旧快照静默覆盖；停止快捷撤回并提供现有版本恢复入口。当前页面的候选状态以持久化的项目状态为准，不因单独 manifest 标志而误报已采用。

取消、失败、过期请求、生成中改文案或切工程均不能改变原音频和 mix 新鲜度。请求级取消接入 AbortSignal 与进程终止；客户端仍独立拦截晚到结果。成功生成但未采用的文件不等于工程内容已变。

## 混音与界面

内部混音统一到 48 kHz，兼容旧 32 kHz、44.1 kHz 和 Vox 48 kHz 输入，避免重采样后时长或时间线偏移。保留 stereo 两声道；单声道人声可交给现有空间层，已经空间化的 stereo 不再被平均成 mono 或重复空间化。保留原始干声。当前切片沿用原有单声道 pan/distance/movement；重混阶段的 V2/HRTF 空间处理与缓存仍属于后续接入工作。

默认界面只显示引擎、参考、参考模式、生成/取消及已出现候选的试听/采用操作。候选列表显示必要时长与状态，技术参数和来源按需展开。采用前原声仍可试听，采用后提供撤回；真实错误、保存失败和需重混继续可见。不得恢复本轮刚删除的开发提醒、长说明或重复统计。

## 已选长文模式（2026-09-09 已完成技术验收）

以 `docs/AI_HANDOFF.md` 中当前已选配方为准：非末语义组置于剩余长文开头完整生成，再安全提取该开头组；最后一组生成真正结尾。只调整语义组间连接，组内天然停顿保留。DeepSeek 可选地给短/中/长类别，实际毫秒来自相邻组内部停顿的等权均值、同类有效样本，最后才用 180/350/600 ms 默认值；保留免费本地分组和默认停顿兜底。所有组选择后再做一次整体响度调整。

补句决策（2026-09-08）：用户明确选择保留固定中性补全文本，理由是此前整段生成后面会变快、变尖。非末组默认输入为“目标组＋剩余正文＋维持长输入所需的补句”，完整生成后仅保留目标开头，补句不进入最终文案和音频；最后一组独立生成真正结尾，不补句。按此成功组合接入，不再把删除补句的对照列为前置或后续待办；补句本身的独立贡献尚未验证。旧样片的 16 句 / 177–196 字符属于复现基线，不是新文案硬上限，不得为凑该长度截去原文。

当前接受样本的人工 group5 替换、裁切 override 与特定 seed/步数不能直接包装成通用服务。安全提取、文本覆盖、首尾不截音、吸气/噪声与声音身份检查需用不同文本验证；不可安全裁切时保留工程原声和已有候选，在服务端记录失败 take 并重生成，不静默截词或将其作为已通过候选。全短句 01/02 停顿比较于 2026-09-08 收到补充反馈：用户此前已听过“原停顿 vs 类别默认停顿”，感觉无明显差异，实际试听日期未知。用户未选新优胜版，class-local 组间策略的当前首选地位不变；该对照不再待听，也不能据此确认首尾无截音或两版完全等价。

2026-09-09 已解决此前 Python/ASR 环境的不确定性：空间环境 `D:\CodexWorkplace\asmr_director_runtime\audio-quality-v1\.venv\Scripts\python.exe` 缺少 faster-whisper/OpenCC；可用环境是 `...\engines\gpt-sovits\env-comfyui-clone\python.exe`，所需依赖导入均通过。后者解释器位于环境根目录，不是旧 helper 所写的不存在的 `Scripts/python.exe`。现有权重在 GPT-SoVITS runtime 的 `tools\asr\models\faster-whisper-large-v3`。产品 ASR 使用离线 CPU/int8，不下载权重、不启动新 HTTP 服务；服务器可用 `ASMR_VOICE_ANALYSIS_PYTHON`、`ASMR_VOICE_ANALYSIS_MODEL` 覆盖安装路径。

当前实施约定：

- `generationMode: "long_text"` 增加可选 `analysisProvider: "local" | "api"`；兼容旧 GPT、非语音和直接生成请求。工作台提供“长文分组”、文本分析来源、生成进度/取消、完整候选试听及可展开的分组试听/重生成。seed、补句、实测停顿来源等技术信息按需展开。
- 输入为 1–500 字符（含标点），最多 12 个连续语义组；每个原始短句必须按原顺序覆盖一次。新文案不会被压成旧样片的 177–196 字符：生成输入保留全部剩余正文，添加延续标点及容量允许的固定补句；必需正文输入超过 500 字符 CLI 限制时明确报错，只可限制补句数量，不静默删正文。容量允许时，非末组沿用接受样片的 16 句长输入构造；末组独立自然结束，不补句。
- 默认本地 Ollama 给语义分组和全部短句边界的停顿类别。用户明确选择的外部 API 复用 Planner JSON-mode 配置，仅发送当前朗读台词，不发送音频。模型分析失败或结构不合格时，明确标记降级到本地标点/规则分组；取消不会触发兜底。保留免费本地路径，不把规则结果标成 LLM 输出。
- 各组串行生成、本地 ASR 核对，仅在有至少 80 ms 词边界保护的足够安静区截取。裁后再次 ASR，检查目标完整性、缺字、重复和后文泄漏。无法确认源词边界时，没有按时长猜测或固定样片 override。每组最多 **3 次尝试（首次＋最多 2 次自动重试）**；配置、超时、取消和无法确认进程退出等故障不会通过换 seed 重试。
- 粗词时间戳可能把真实停顿错误计入下一词。边界细化只搜索“较早粗边界前 0.5 秒至较晚粗边界后 0.65 秒”，最多检查 3 个附近静音候选，并要求截点两侧各有至少 80 ms 实测安静。左右独立 ASR 必须分别识别完整目标与完整后文开头；下一句首音缺失、目标尾音泄入右侧或仅单侧匹配均失败。最终裁后音频仍再次核对。这修复时间戳误差，不导入人工样片截点，也不降低文本完整度或 80 ms 时长保护。
- 静音检测先用严格阈值 `max(-68 dBFS, 峰值帧 RMS - 40 dB)`。必要时才使用有界补充阈值 `min(-60 dBFS, 峰值帧 RMS - 30 dB, 局部20%分位底噪 + 6 dB)`，且它必须高于当前严格阈值才启用。严格和适配候选共用最多 3 个检查名额，相近截点不重复尝试；每侧 80 ms 保护与全部独立 ASR 检查均保留。验证区和阈值作为可选服务端 `cutValidation` 记录，仅把验证区与最终裁剪范围相交、且确实连到文件末尾的部分计入尾静音。拼接时扣除该已保留时长，最多在验证安静区内淡出一次 10 ms。前缘安静检测与已选内部词间隙算法不变。
- 内部停顿使用相邻ASR词的真实间隙，按1ms取整。目标字词时间验证通过后，录制元数据接受有限、非负且不超过10000ms的间隙；自然停顿较长不单独拒绝已验证的目标台词。原音及实测值完整保留，不截短、不重定时。沿用原−1e-6ms浮点容差，范围内的微小负向计算误差按0记录；更大的负值、非有限值、超上限或无法确认的边界仍失败。原组间连接配方仅采用0–1200ms样本，0计入组均值，较长的已记录停顿排除在估算外。短/中/长范围为120–260 /261–480 /481–900ms。连接先取相邻两组有效样本均值的等权平均，落入目标类别才使用；否则取“分析类别相同且实测时长也在该类内”的有效内部边界均值；再无有效样本才用180/350/600ms默认值，最终按10ms取整。不使用每字时长或前后语速差公式。2026-10-07因完整目标含自然1.48秒源ASR间隙却被旧1200ms检查拒绝，明确区分录制值与拼接样本上限。
- 保留组音频和组内时间结构。组间只补足扣除首尾已保留安静时长后的差额；已有安全边缘更长时保留自然停顿，不强裁人声。完整成品只进行一次整体 active-RMS 调整，目标 −27 dBFS、峰值不超过 −1 dBFS。各组素材和拼接元数据独立于 Project JSON。
- 单组重生成沿用原候选计划和其他已验证组素材，创建新的完整候选，并重算连接和整体响度；不修改或自动采用旧候选。复用前检查归属、内容/选项与素材可用性，继续使用既有采用/撤回和时间线规则。
- 一次运行的排他锁覆盖分组、全部 TTS 和 CPU ASR。每次 TTS 与 ASR 各有 5 分钟超时，整个长文任务上限 30 分钟。取消会停止当前进程，并等待确认退出后释放锁；无法确认退出时保留锁和工作目录，禁止接着启动下一次 TTS。服务端证据位于 `voxcpm2-product/long-text/<运行ID>`，ASR 临时目录为 `voxcpm2-product/analysis-runs`。
