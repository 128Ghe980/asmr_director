# 本项目目录与清理规则

用户于 2026-10-25 明确纠正：`I:\AI` 是多个项目的母目录，`I:\temp` 不是本项目的输出目录。不得再以任务名、日期或功能名在这些母目录下不断新建本项目文件夹。

## 固定归属

- 源码和受版本控制的文档：`D:\CodexWorkplace\asmr_director`。
- 本项目唯一外置数据根：`I:\AI\asmr_director`。以后复用这个根，不新建平级 `asmr-director-*`、`H3-ASMR-*` 或日期目录。
- `artifacts/`：当前可交付包、导出结果。H3 批跑包放 `artifacts/h3-asmr/`。
- `qa/`：验证日志、回执、测试素材；按功能分组，日期只放在组内。
- `runtime/`：本项目运行环境、模型、用户音频、声音参考、应用持久数据。
- `service/`：服务启动脚本及服务日志。
- `cache/`：可重新生成的构建、模型编译和中间缓存。
- `archive/`：仍需保留的旧版交付物；重复展开件经压缩包逐文件核对后可删除。
- `tmp/`：本项目短期临时数据，工作结束时清理自己创建且不再使用的文件。
- 外置数据盘不可用时，小型开发临时文件仅用源码目录 `.local/tmp/`；大文件先检查空间，不回退到共享 `I:\temp`、`I:\AI` 或 C 盘根目录。

用户明确提供的外部输入可以就地只读。例：`I:\temp\文生视频.json`；读取它不意味着获准将输出放在同一目录。其他项目和共享模型的外部目录属于依赖，不因名字相近而移动或清理。

## 执行规则

1. 创建文件前确定所属子目录；先复用既有目录，不能因为任务变化或日期变化就在项目母目录旁另开一棵目录树。
2. 测试框架、脚本默认输出路径、服务配置都应遵守同一根目录。不要用历史文档里的旧绝对路径重新创建旧目录。
3. 历史证据保留原始时间、路径和哈希；通过数据根的 `storage-map.json` 查新位置。原始回执不因迁移而伪造成“在新位置当时执行”。需要重跑的脚本先更新路径再执行。
4. 移动或递归删除前，用绝对解析路径确认目标落在已核对的本项目范围；不越过 reparse point 清理其指向的数据。模型、用户原音、参考音频和运行状态只迁移，不以“临时”推断可删除。
5. 清理重复展开件前，对照保留的压缩包逐文件核验内容；清理缓存前确认没有活动使用者。保留删除清单与释放的逻辑字节数，不把迁移的字节数算成释放空间。
6. 涉及活动服务时，先核对启动配置、进程、正在执行的任务和引用，安排最短必要切换；迁移后验证服务与关键素材仍可读取。

本规则同时适用于本轮根 agent、子 agent 和后续接手者。目录迁移只整理存储，不改变产品路线、音频选择、用户工程或模型质量结论。
