## 意图与问题证据

用户检查历史「雪夜归家」视频包，指出接外套只等待、递茶后角色继续持杯，以及长时间相同景别和姿态。只读检查 `I:/temp/雪夜归家` 的 24 镜提示词，24 镜均中近景、19 镜标注 static、22 镜为 continuous。第三镜明确写 waiting to take the coat；第七镜只写 offers the cup，第八镜又写 holding a steaming cup。这里确认的是提示词已有的问题，不代表检查过真实视频执行或人工听感。

旧生成器对白镜主要只看基础场景、当前台词和时长，连续时另看上一镜画面/动作/机位；前后台词上下文只给无对白镜。旧连续规则又要求同一场景、光线、景别与机位、不另换位置，叠加中近景露嘴和轻微单动作，容易把整批压成保守姿态。程序缺少明确的道具交接结果和跨镜状态推进要求。上述是代码与实际提示词的对应事实，不把某条规则当作模型选择微笑的唯一因果。

## 已实现范围

逐镜生成增加完整脚本顺序、当前镜头位置、相邻语义和可用实测时长；其他文案无需先生成音频即可作剧情上下文。工程 start、段后等待、未生成语音的估计时长不编入动作节奏。既有其他镜头的标题、画面、动作和环境声可作为可选语义上下文，不强制继承机位或复制完整 H3 prompt。

动作规则围绕一个主要事件及可见结束结果，保留合理静止；区别说话者自身动作、邀请听者做事、过去事实、未来计划和条件句。连续镜头保持角色与道具状态，允许同场景自然移动、落座和跟随；脸嘴在说话时可见，重要手部与道具也应入画，不再固定整批中近景。角色参考外貌、台词、原音、独立/连续偏好和实测镜长继续保留。

全稿上下文指纹只保护进行中的请求：单镜及批次响应落地前检查最新相关输入，后文或其他语义上下文变化时丢弃旧响应；不把全稿身份写成旧分镜的新增有效性条件，不自动让历史整批分镜过期。

新增固定服务端外部文本 API 的 `POST /api/storyboard-review`，请求 `{project, editableClipIds}`。全稿与全部当前分镜作为上下文，只返回必要的文字修订和原因，不评分、不要求通过、不递归校对。只允许标题、画面、动作、机位和无对白环境声文字变化；台词、音源、镜长、顺序、镜头偏好与素材绑定由代码保留。原本有效的下游前镜指纹随文字修订重绑，保留其自身文字，原本过期的镜头不复活。

真实输出暴露内部素材 ID 缺号导致镜号错绑，以及模型输出无修改占位项的问题。最终模型内部只使用明确的三位 `shotNumber`，由服务器映回原 `clipId`；`after` 允许只返回真正改变的文字字段，由服务器合并完整 before/after。无实质变化的项目忽略，实际越权字段、非法编号或无效文字仍整批原子拒绝；不靠把错误镜头按数组位置猜回去，也不允许模型改音源等元数据。对外 review 及 UI 合同保持不变。

批量分镜结束后，仅在当前整批分镜齐备且本轮有成功保存结果时自动校对一次。记录本轮成功镜头的 exact shot JSON，自动调用前排除已被手改的镜头，API 回复也再次限制可改 IDs。分镜尚缺或过期时略过并提示可稍后手动校对；失败或取消保留生成结果，不增加后处理或导出门槛。

旧项目可从「批量更多操作→整批校对」手动调用。先显示最小改动摘要和可展开差异，用户点「应用修订」后才修改，避免静默覆盖未知历史手改。应用或自动修订先保存工程库，再更新页面；保存失败保留原分镜。摘要默认紧凑、差异默认收起并按页面自然展开，不新增内层滚动。

撤回使用反向文字补丁和当前相关指纹保护，不回滚整个工程；后续无关音频、音量、空间与导出设置保留。分镜或来源后续已变动时不能套回旧校对。待应用建议和撤回记录只在页面内存，应用后的分镜随当前工程及短句/整段工作区保存；不增加持久化手改标记。工程/工作区切换、取消、卸载和晚响应均有 token/session/指纹保护，校对期间与生成、后处理互斥，取消后不继续占用已结束的批量队列。

主要代码范围：`storyboard-context.ts`、逐镜 `clip-storyboard-service.ts`，`storyboard-review.ts` / `storyboard-review-service.ts` / 新 API，`video-plan.ts` 的当前前镜引用重绑，以及 `studio-app.tsx`、批量操作组件和新校对结果面板。对应双语规格：[中文](../specs/2026-10-23-storyboard-context-and-review.zh.md) / [English](../specs/2026-10-23-storyboard-context-and-review.en.md)。
